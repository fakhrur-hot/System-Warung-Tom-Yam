# Central affiliate catalog

`partners.json` is the one place affiliate links live. Edit it here, on `main`, and every café's
ordering page picks the change up within ~5 minutes — **no rebuild, no per-café edit, no deploy of
any café site.**

## Why it is not in `website/`

A café's site is built from `website/`. Anything inside it is copied into every café's deployment,
which is exactly the duplication this design exists to avoid: one stale copy per café, each needing
its own update. This folder is deployed on its own, by its own Cloudflare Pages project, from
`main` only. Café branches may carry the *file* in git (they are cut from `main`), but they never
serve it and never read it — the page always fetches the central URL.

## Why the file is not called `ads.json`

EasyList and its derivatives block requests by filename and path: `ads.json`, anything under
`/ads/`, and paths containing `affiliate` are all matched. Brave and uBlock Origin would drop the
request, and **every café would silently show nothing** — a failure that looks exactly like a
working config, because nothing errors. Keep this file's name and path neutral. Do not "helpfully"
rename it.

## Shape

```json
{
  "default": { "subId": "menu", "products": [] },
  "byCafe": {
    "Tani Tom Yam": {
      "subId": "tani-menu",
      "products": [{ "href": "https://s.shopee.com.my/XXXX", "img": "", "alt": "Chilli grinder" }]
    }
  }
}
```

- `byCafe` is keyed on the café's `cafeName` from its own `app-config.json`, matched
  case-insensitively. A café with no entry gets `default`.
- `href` — the short link **generated by the Shopee affiliate portal**, verbatim. Do not hand-build
  `shopee.com.my/product/{id}?affiliate_id=...`: that is not a documented tracking form, so it earns
  nothing while looking affiliated. The portal's short link already carries attribution.
- `img` — optional. With an image the placement renders as an image tile; without one it renders a
  text card with a "Shop on Shopee" call to action. Never nothing.
- `alt` — the label a customer reads. Write it for a human, not for SEO.
- `subId` — Shopee reports this back, so it is how you tell café-QR earnings from your other
  channels. Appended only when the link does not already carry its own `sub_id`.

## Precedence

A café's own `app-config.json` `shopeeAffiliate` block, if it has one, **wins over this file** —
that is how a single café curates its own list or opts out entirely. With no local block (the
normal case, and what a freshly registered café ships with) this catalog fills the slots.

## Hosting

**Today: GitHub raw on `main`** — the default baked into the build generator:

```
https://raw.githubusercontent.com/fakhrur-hot/System-Warung-Tom-Yam/main/promos/partners.json
```

It works with no infrastructure at all: the repo is public, raw sends
`Access-Control-Allow-Origin: *` (verified), and it caches for 5 minutes. Push an edit to `main` and
every café has it within minutes.

Its limit, stated plainly: raw is rate-limited and GitHub discourages hot-linking it from
production. It is fine at café scale and wrong at chain scale.

**Later: this folder's own Cloudflare Pages project** — the upgrade path, needing no code change.
`_headers` in this folder is already written for it. Create a Pages project separate from any café
site:

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Framework preset | None |
| Build command | *(empty)* |
| Build output directory | `promos` |

Then repoint the cafés by setting `partnerCatalogUrl` in each café's `app-config.json` (or
`VITE_PARTNER_CATALOG_URL` at build time) to `https://<project>.pages.dev/partners.json`. No café
needs a code change, and cafés can be moved one at a time.

Whatever the host, a catalog that is missing, blocked, or malformed resolves to "nothing
configured" — never an error, and never a broken ordering page.
